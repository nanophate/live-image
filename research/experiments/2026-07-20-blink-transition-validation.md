# Blink close/reopen transition validation

Run date: **2026-07-20**

Base merge: `e8e4314d3c1deb9413921f0642113efae0fe7db8`

## Protocol

**Decision.** Extend the separate motion-comparison Viewer with a bounded blink
timeline rather than relying on endpoint screenshots or refresh-rate timing.
Use the exact pulse function shared with `LivingImagePlayer.triggerBlink`, keep
automatic idle disabled, and render all samples sequentially through one player.

The shared 160 ms pulse is sampled at these normalized time fractions:

```text
0, .10, .20, .30, .40, .42, .50, .625, .75, .875, 1
```

This produces blink amounts:

```text
0, .2381, .4762, .7143, .9524, 1, .8621, .6466, .4310, .2155, 0
```

**Decision.** Render rejected or blink-disabled assets as an explicit skipped
timeline with no allocated frames. For rendered timelines, compare the 180 px
preview RGBA values of the first open frame and the reopened frame. Any changed
pixel is a deterministic recovery failure, independent of visual judgment.

## Visual review

**Confirmed.** The two supported anime portraits showed progressive close,
explicit full closure, and progressive reopening without a face-wide warp. On
the mcproject case, the large white/red iris highlights remained recognizable
during partial closure, disappeared with the closed eye, and returned in the
reopened frames. The final open frame was pixel-identical to the initial open
preview, so no persistent highlight crushing or state residue was observed.

**Confirmed.** Both compiler rejects displayed `Not rendered — Asset rejected
by compiler` instead of forcing a blink. The painted `limited` case still
rendered because the current compiler has no support-domain gate; that known
problem is not reclassified as a transition success.

## Limits and next action

**Open.** This is deterministic sampling of the same runtime pulse curve, not a
screen recording driven by `requestAnimationFrame`. It verifies the render path
and state recovery but does not measure dropped frames, display refresh timing,
or perceived speed on low-end devices.

**Open.** Endpoint equality is measured on bounded 180 px previews. It is a
strong state-residue check, not a full-resolution perceptual metric for every
intermediate eyelid seam.

**Decision.** Keep this timeline in the comparison Viewer as a regression
surface. The next runtime experiment may exercise `triggerBlink` under recorded
frame times, but compiler work should first follow the independently calibrated
warp-support protocol in
[`../support-domain-gate.md`](../support-domain-gate.md).
